# Заметки по Git

1. Git — это система контроля версий, она следит за всеми изменениями в проекте и хранит всю историю у меня локально, в папке .git, которую обычно даже не видно в проводнике
2. В git есть 3 зоны — сначала я просто меняю файлы на диске (рабочая директория), потом делаю git add и файл попадает в staging (это как "подготовил к сохранению"), и только после git commit это реально фиксируется в истории
3. git status — самая полезная команда, показывает вообще всё: что изменено, что уже добавлено в staging, а что git вообще ещё не видит
4. если хочу быстро глянуть историю коммитов, использую git log --oneline, там всё компактно в одну строку на коммит
5. коммит — это по сути снимок проекта на конкретный момент + сообщение, зачем я вообще это менял, чтобы потом через месяц не гадать что я имел в виду

# Заметки по Git Flow

1. main — ветка, где лежит только стабильный код, туда напрямую руками ничего не пушим
2. develop — сюда сливается вся текущая разработка, это как рабочая версия проекта
3. feature/* — создаю такую ветку под каждую задачу/фичу, всегда от develop, и когда закончил — вливаю обратно в develop
4. release/* — нужна когда готовим версию к выпуску, тут всё дособирается перед тем как отправить в main
5. hotfix/* — если что-то срочно сломалось в проде, делаем ветку от main, чинafter и вливаем сразу и в main и в develop, чтобы фикс не потерялся

## Таблица веток

| Ветка | Откуда создаётся | Куда вливается | Зачем нужна |
| feature/* | develop | develop | новая функциональность / задача |
| develop | — | main (через release) | текущая разработка, всё собирается тут |
| release/* | develop | main и develop | подготовка версии к релизу |
| hotfix/* | main | main и develop | срочный фикс прода |
| main | — | — | стабильная, production-ветка |

## Полезные команды, которые я использовал

- git status — посмотреть текущее состояние
- git add <файл> — добавить в staging
- git commit -m "..." — зафиксировать изменения
